# 自定义动画：源动作、客户端骨架与最终绑定

适用新动作导入、重定向、重新 Cook 或轨道映射修正。网格权重没改也需要检查。外部 VMD 的进程内预览另见 [运行时 VMD](runtime-vmd-mod.md)，不把 cooked 压缩表的检查直接套到 VMD 文件上。相机或贴图任务无需进入本分支。

## 1. 完整源合同

保存 clip 身份、源 rig、完整层级和 reference TRS、轴/单位、四元数顺序、local/world 语义、根与骨盆、helper、手指、表情、时长、采样和循环。

人物、家具和道具在同一源时间中的相对关系一并保留；源 owner 可能是床或场景控制器，骨盆不是整个场景锚点。不同格式用对应的真实解码器，不将形态肌肉值当骨骼四元数。

## 2. 重定向

先证明动作在自身源 rig 上能重建，再做一次 source 到目标坐标转换。按名称和解剖语义映射，确认层级、rest、骨长、掌面、足部及 Twist。

源/目标局部静止轴不同时不能复制局部旋转。世界旋转差值只能提供待检查基线；接触、骨长和姿态语义仍需适配。目标局部轨由正确父变换求得，不把世界位置重复写到每条局部链。

根运动、骨盆位移和 Actor 放置有明确分工。双人共用源时间与锚点。新增 IK/追视等修正逐项加入，避免掩盖原始绑定错误。

HS2 动作另执行 [脚部与高跟鞋](footwear-retarget.md)。

## 3. 客户端 Skeleton 才是运行依据

独立读取当前使用者实际挂载的 Skeleton，包含有意启用的覆盖。记录来源、资源身份、按序骨名、父级和 reference TRS。作者工程的同名 Skeleton 不能代替。

导入前和 Cook 后比较作者/客户端合同。导入可能新增辅助骨并改变后续索引；同名、同路径、同 GUID、骨数相同都不足以证明兼容。不要为了单个动画覆盖公共 Skeleton。

骨数按目标族确定，不固定某个案例数字。未驱动辅助骨可以不同，但被驱动名称、层级、参考空间和最终映射必须正确。rest 或层级不同需要重定向，不能只改索引。

## 4. 最终双映射检查

1. 转索引前独立保存每条轨道预期骨名。不要从待测映射反推出期望值。
2. 读取最终暂存 cooked 动画，核对每条轨道索引在客户端骨表中指向预期名称。
3. 拒绝缺失/歧义名称、负数、越界、非预期重复目标及范围内指错骨的问题。
4. 同时检查 TrackToSkeletonMapTable 与 CompressedTrackToSkeletonMapTable。只检查可编辑属性不足。
5. 编码器若裁剪或重排轨道，按其解码后的身份对应；未知压缩格式不能按旧偏移猜测或跳过验证。
6. 稀疏动画不要求驱动所有骨，检查实际驱动集合。

本包没有解码器或自动验证脚本。缺少对目标格式的可靠读取能力时，记录未验证，不把成功退出码或字段数量当成绑定通过。

## 5. 解码与真实网格回放

用独立客户端参考解码最终 cooked 关键帧。必要的只读分析骨架从客户端合同生成，明确只用于分析，不进入发布包。

真实目标网格的权重索引属于网格自己的参考骨表。即使名称集合和数量相同，也需按名称/父级对应客户端骨表，使用网格 bind 矩阵蒙皮，不能直接套客户端数组索引。

对每个新增 clip 观察初始、极值、恢复或循环帧及连续播放。检查过程中不要自动改名、拟合新 rest 或修正姿势，否则会遮蔽绑定问题。

## 6. 封包与实机

封包回读确认检查过的动画字节被完整保留。最终输出变化时重验，不沿用旧结论。

客户端通过预期使用者测试对应动作；播放逻辑有变化时检查停止、移动取消和恢复。离线不模拟完整 AnimBP、IK、布料、LOD、胶囊或控制权，缺口分别记录。

交付区分：源预览、客户端骨架绑定、最终 cooked 回放、Pak 完整性和客户端运行。多个自定义动作同时爆体而源预览正常时，优先检查最终压缩轨道绑定，再继续坐标、权重和后处理诊断。
