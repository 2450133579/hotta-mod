# 运行时 VMD：路线、实现与交付

## 适用范围与案例边界

2026-10-12 在国服 PC 原版客户端上制作过 UE4SS v3.0.1 + 原生 DLL + Lua 的进程内预览 Mod。它读取外部动作 VMD、可选表情 VMD 和 WAV/MP3，复用当前角色资产，无需为每份文件运行 Blender、UE Cook 或独立后台转换程序。它是运行时功能 Mod，不是单个 Pak；已有 Pak 目录不能证明存在外部文件加载接口。

该案例的客户端、加载器二进制和角色骨架条件需要重新确认，不能推广为国际服、重制版、任意更新或所有角色均可用。标准表情是近似骨骼重定向，不等同于原 PMX 的所有自定义 Morph。

## 按层制作

1. 先验证加载框架在当前客户端初始化，再取得本地玩家、实际主 Mesh、骨名/父级/参考 TRS。菜单出现不能证明播放接口兼容。
2. 原生 DLL 只处理 Windows 文件选择、Unicode 文件读取、计时和音频；Lua 处理 VMD 数据、语义重定向和游戏对象。接收者不需要安装制作工具。
3. VMD 是二进制输入，不能送入 load/loadfile。VMD 2 骨骼记录为 111 字节，Morph 记录为 23 字节；名称使用 CP932 解码，检查长度、计数、有限数值并整理轨道。
4. 骨骼位置使用对应 Bezier 曲线，旋转使用四元数插值；Morph 权重按关键帧线性采样并限制到有效范围。动作文件内表情与独立表情可合并，独立文件同名轨道优先。
5. 支持源文件实际使用的 FK、足 IK、左右眼和手指语义。仅实现足 IK 不能覆盖不含 IK 轨道的 FK 动作。目标轴、单位、骨长与层级按当前客户端适配；案例中的位移倍率不是通用常数。
6. 动作、表情、音乐共用播放进度。暂停、恢复、停止、循环和音频短于动作时的行为必须明确，不能以三个独立计时器近似同步。
7. 保存原角色状态，完整处理骨骼网格、静态饰品和自有音频；渲染确认后才隐藏原表示。恢复与热重载机制见相机/互动技能的状态事务。

## 框架与原生桥接

UE4SS v3.0.1 的 Lua ABI 需按实际 DLL 核对。案例中框架使用其自身的 Lua 5.4.4，未导出普通 lua_C API；原生模块通过已审计的宿主包装器调用，按 DLL 哈希和执行页归属约束，未链接第二个 Lua 核心。把另一套 Lua 编进模块并混用 lua_State 是 ABI 风险，不能用“都是 Lua 5.4”代替验证。

客户端 FText 构造函数扫描曾出现歧义，使用实际调用点解析到真正的构造函数，并通过框架的字符串构造/回读检查。不能用空实现、猜地址或绕过验证冒充兼容。签名和宿主包装器都属于版本条件，不是稳定公共 API。

Native DLL 会因菜单线程而保持加载。同名 DLL 覆盖失败时，采用新版本文件名及独立窗口类，并只隐藏同一游戏进程内自己的旧窗口；Lua 和 DLL 的实际修订号都写入日志，防止源码更新但仍运行旧 DLL。

## 分类故障入口

- 源网格、权重、法线和运行时表示如何分界：Blender 检查技能的“检查约定”“动态与接缝”。
- 零缩放、骨骼初始化崩溃、灰脸、黑材质、静态颈饰和 Unicode 路径：资源诊断技能的“资源与外观诊断”。
- cooked 压缩轨道与运行时语义映射如何分别检查：资源诊断技能的“客户端动画映射”。
- UE4SS 调度锁、STA 文件选择器、MCI 设备创建线程、暂停/循环及热重载残留：相机/互动技能的“功能制作诊断”“互动与恢复”。
- 可分享包的目录、依赖、隐私清理、清单和回退：本技能的“封包与安装”。

## 证据与交付口径

案例实际验证过两类 FK/IK 动作解析、游戏预览、独立表情读取、脸部外观恢复、颈饰接入和带音乐播放/自然停止；音频同线程管理在独立测试中完成跨调用线程的多次重开、暂停和恢复。单张颈饰画面不证明每一帧均无穿插；安装了 Montage_Play 钩子不等于基础动作绑定已完成实机验收。界面显示表情轨道数量，也不表示所有模型专属表情已适配。

交付分别记录解析、骨架回读、连续播放、视觉、声音和恢复结果。用户要求结束排查并整理版本时可停止扩展测试，但不能补写未执行的验收。
