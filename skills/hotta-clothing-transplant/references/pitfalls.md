# 移植中遇到的坑与解决方法

这些来自原版国服 PC 行路的 Anastasya、旗袍与 MD 泠鸢泳装移植记录。工具版本、骨数、目录、材质编号和局部数值只属于相应案例；MD 源工程特有问题集中见 [MD 导出与接入](md-garment-workflow.md)，具体过程见 [MD 泳装案例](md-swimsuit-case.md)。

| 症状/误判 | 原因 | 解决与验证 |
|---|---|---|
| UI 名称和模型编号混用 | 配置行、展示名称及实际 Mesh 是不同标识 | 配置表引用和运行时活动组件一起确认，排除活动 Mod 覆盖后再提取官方基线 |
| 提取 Body 就带入外部裸身 | 一个网格同时包含裸皮、袜靴、手套和饰件 | 用面、UV、材质图和连通块细分，保留源面身份，导出清单检查裸身和脸发是否混入 |
| 肩部毛边因 Hair 材质被删掉 | 材质用途不能由名字决定 | 查看实际部位，保留 Fur/Shell 肩饰，排除真正的头发对象 |
| 胸口碎片、髋部丝袜扁片或体表断面 | 参考体表缺失：曾按贴图颜色漏掉胸部，或复用省略髋部/小腿的旧作者身体；最近点吸附把衣料压到错误边界 | 检查实际区域面覆盖、边界和权重；保留原有可见皮肤，先补对齐的官方缺失体表，再从可信源面恢复局部衣料。不能仅凭对象名推定身体完整 |
| 胸腰衣料被拉成碎片或层间重叠 | 对多层面做不受限制的逐点最近面投影，装饰也被压到身体上 | 恢复完整源衣料，分区使用平滑变形场保留层距，局部修正控制范围和法线 |
| 静止正常，胸衣在动作中裂开 | 胸杯只部分耦合到身体；贴身腰段仍由裙摆辅助链带动 | 整个贴身胸衣连续取样原版身体权重，检查相同原生动作帧 |
| 松散胸部荷叶边走跑时猛烈折叠 | 把贴身胸衣规则套到外层褶片，逐点胸部权重或固定高度胸骨混合破坏整层连贯性 | 外褶使用经动作验证的连贯上躯干跟随，带子分区绑定；实体上衣必要时加原版体表蒙皮内衬，不能把透明衣料一律封实 |
| 腰缝补完仍有黑三角，或切下身后前臂缺失 | 不规则边界按极角排序交叉；全局高度同时选中不同身体部位 | 用真实边邻接环与弧长配对补缝，检查目标边界和法线；上下身分离加入骨组、侧别和区域约束，具体步骤见移植流程 |
| 静止袖饰正常，抬臂仍留在胸旁 | 左袖 100% S_Armor_L，其父级是锁骨；右袖/毛边大量绑定 Cope 披风链 | 查看父级和实际骨骼运动，改为对应上臂跟随、肘部柔性过渡；披带上缘同步连接袖饰，下段保留辅助链 |
| 袖饰动了，小菱形仍悬空 | 检查时忽略了三角数很少的小连通块 | 同一部件的小装饰一并检查，取消仅按面数筛除的小块，保证饰件与承载衣料同动 |
| 手套上缘动作穿出皮肤 | 上缘与最终身体的权重场不一致，或不同三角拓扑的插值在动作中产生间距不足 | 限定同侧重采样上缘并调间距；必要时用原版局部体表拓扑、服装 UV 和同源蒙皮做内衬，严格限在实际覆盖面内，保留手指及已接受区域 |
| 补肤省略后裸露胸口出现小三角洞 | 把埋在皮肤里的项链当遮挡物，删除其下方皮肤 | 保护裸露颈胸区域，将独立项链饰件贴合到皮肤外；不用删除裸露皮肤掩盖首饰埋入 |
| Gauze01 套错图 | 凭名称猜成 Dress 图，实际配置引用 Body01 | 读取源材质 JSON 的真实 _MainTex 引用和混合配置，按引用赋图 |
| 实体服装意外透明，或把“透肉”一律改成透明材质 | 主图 Alpha 可能承载数据；丝袜的透肤外观也可能已画进不透明纹理 | 检查源配置、实际 UV 采样和 Alpha 用途；保留真实薄纱的透明，不凭文件名套透明，也不全局强制不透明 |
| 新衣料光照/细节不对 | 新 UV 继承了原时装的法线、光照图和染色遮罩 | 私有衣料配置正确/中性输入；本例使用中性光照图、无染色遮罩和独立平面法线图，原生皮肤保持自身材质 |
| 绕序与法线相反 | 坐标手性转换只处理了位置或重复翻面 | 比较几何面法线与来源法线，统一转换绕序、UV 角序和法线；再检查 cooked 切线 |
| Blender 复制后权重归零 | 替换 Mesh 后调用 vertex_groups.clear 会移除关联权重 | 在清除前保存来源组名和每顶点权重；重建组后明确回写，再检查归一化和零权重 |
| Blender 材质清空重建后全变同一槽 | materials.clear 可重置面材质索引 | 保存每面的 material_index，重建材质槽后恢复索引；不要只比较槽名 |
| 读取 .blend 的对象名单突然变成对象实例 | libraries.load 会将提供的列表原地替换为加载结果 | 保留独立的名字列表，把副本交给加载器，避免后续拿 Object 当字符串索引 |
| 动作检查文件被误当 rest 生产文件 | 移除 Action 后骨骼 matrix_basis 仍可能保留上一帧姿势 | 生产使用已保存的 rest 作者文件；检查结束清理 Action 并重置 pose basis，验证实际保存状态 |
| FBX 多出额外骨骼根节点 | 导出对象结构与 UE 的 Armature 处理约定不一致 | 检查实际导出骨序和层级；本例使用 Armature 对象名避免额外根节点，Cook 后再次回读 |
| UE 4.26 设置材质参数返回 false | 本机 4.26.2 库的返回值实现不反映实际写入结果 | 使用反射的 TextureParameterValue / ScalarParameterValue 数组，update_material_instance 后通过 get 接口回读实际值，不能忽略真正失败 |
| 私有材质把作者占位资产一起带进游戏 | 作者工程借用占位父材质/参数声明辅助 Cook | 私有 MIC 不新增未经验证的静态排列，仅引用正确运行时父路径；暂存排除作者父资源、Skeleton 和 _AuthorOnly，扫描实际引用 |
| 工具脚本失败但宿主进程退出码为 0 | UModel 参数/游戏类型不匹配，或 Blender/UE 的业务脚本报错后宿主仍正常退出 | 原版与新 Cook 资源分路；检查错误日志、成功标记和真正产物。Blender CLI 设置 --python-exit-code；UE Python 导入还要核对材质槽与资源报告，不能以外壳退出码代替成功 |
| HT 转换完成却没有 Sig | 本机 HT.exe 只转换 Pak 外壳版本 | 按用户已验证的当前客户端方法配对 Sig；本次复用指定模板并同名，不声称进行了新的密码学签名 |
| 摄像头/头发辅助物出现在导出中 | 隐藏视图或设置检查用途不等于生产排除 | 对最终导出对象和暂存资源清单显式过滤，检查脸发资源未被写入包 |
| 安装两次或仍加载旧版 | 客户端 PatchPaks 是 junction，或旧候选仍覆盖同路径 | 找到物理目录，只安装一次；备份并撤下旧版后重启挂载，比较安装文件哈希 |
| UV 最近点修复后衣料突然跳到别处或出现尖刺 | UV 重叠、左右复用或不同部位共享同一图集，单靠 UV 不能证明源几何身份 | 回到保存的源面/顶点身份与细分来源；按物理部位、侧别和拓扑约束对应。新衣料保留面角 UV，已验证的局部源数据可直接复用，不必重拆全模型 |
| 裙片在走跑中拉碎，或被抬出的腿穿过 | 下垂段全部绑腿，或反向修正后全部留在不随迈腿运动的辅助链；短裙的人为骨盆混合也可能阻止让腿 | 根部保持连接，按形态选择辅助链与同侧大腿过渡，或验证短裙的连贯原版身体权重与局部净空；同帧比较穿模和图案拉伸，不固定套用案例比例 |
| 手套内衬在上臂形成黑色锯齿 | 只用面中心到手套的距离选区，三角面角仍越过真实袖口 | 检查全部面角与实际衣料覆盖，保留服装 UV 和局部原版权重；缩回内衬选区并复查同一屈肘/跑步帧 |
| UE 导入新衣服却保留旧衣服的槽名 | 对旧 Mesh 做 replace_existing 时保留原有材质槽，几何新导入不代表槽已替换 | 只在独立作者工程中准备干净 Mesh 导入目标；逐槽核对名称、材质资源和纹理引用，原游戏文件与既有可用作者版本保留 |
| Cook 权重与作者浮点值不完全相等 | 本例导入裁掉小影响，再归一化并用 8-bit 权重编码，残差回到最大影响 | 比较当前位置对应的影响骨集合及已确认的裁剪/量化误差界；本例规则和数值见旗袍案例，不推广到其他客户端，不用任意大阈值“通过” |
| Cook 后检查器 StopIteration，却已生成模型 | 只搜索 .psk，高顶点数导出实际为 .pskx | 同时发现两种扩展名，检查实际 chunk 和索引宽度；适配回读器，保留用户接受的网格密度 |
| Cook、UModel 和 Pak 回读全过，游戏却卡在加载 90% | 本次额外使用 -unversioned 清空资源版本信息，与此前可用 Cook 路线不同；分析器指定 UE 版本能读取，不代表定制客户端同样能解释 | 按已验证路线去掉该参数，独立输出完整重新 Cook；核对资源头及原模型回读不变，再做客户端复测。MD 泳装 02 已获用户确认正常，详细对照见案例；不推广为所有客户端禁止无版本资源 |
| 原始 PSK 与新 cooked 的脚趾 bind 有微差 | 可能是已存在于此前接受版本的导入差异，不能仅凭警告归因于本次 | 对照此前接受 cooked 的全部骨骼局部位置与旋转，记录两类基线和真实差值；不同于任意放宽阈值，案例见 MD 泳装记录 |
| 搜主索引没有资源名，却实际存在包覆盖 | 现代 Pak 可能把文件名放在独立完整目录索引，主索引只含散列/入口信息 | 按已验证格式读取完整目录索引，或用成功列出真实清单的工具；同时检查时装表目标行的资源路由 |
| 验证脚本突然找不到 bpy，SciPy 无法导入 | 工作目录的 inspect.py 遮蔽 Python 标准库 inspect，普通 Python 误加载 Blender 专用脚本 | Blender 脚本用明确任务名称，避免与标准库同名；修正模块发现路径后重新运行受影响审计 |
| Blender 空场景检查中断或 MCP 无法连接 | 工厂空场景可能没有 World；未启动服务不等于源模型不可用 | 检查实际环境与数据，按需创建诊断 World；有已确认的 Blender CLI 时在工作副本中继续，保留日志并确认保存文件可重新读取 |
| UE DDC 写入用户目录失败 | 默认 Boot/本地缓存落在无写权限目录，仅设置一个缓存环境变量未覆盖全部图 | 使用当前版本支持的任务缓存图，把 Boot 与 Local 放在可写作者目录；通过实际日志确认路径，缓存报错不应混同模型错误 |
| 自动安装在进程检查处退出 | 进程路径读不到或 WMI 查询受限，尚不能确认需要结束的具体客户端 | 不猜路径或强制结束；用可验证的客户端入口/用户操作继续。核对最终物理安装文件与交付哈希，用户完成验证记录为用户验收 |

## 修复时保留证据

分别保留原始输入、修改作者文件、选区来源、变化顶点/面列表、源 UV/法线与动作对应帧。纯权重修复可用位置/UV/材质不变和受保护区域哈希证明范围。

最小复核应回答实际问题：袖饰是否跟上抬臂、肘部是否仍连续、胸口是否保留正确裸露边界。更多数字或更多视图不能代替观察真正失败的姿势。完整 Cook、Pak 回读和用户实机确认是不同证据，不把它们合并成一句空泛的“测试通过”。
