# 行路 → 透肉黑丝旗袍案例

## 任务与来源

2026-10-14，素材为 shuiling+yukiyame 的“标准黑丝+透肉黑丝旗袍”压缩包。两套 PMX 并存，用户选择“透肉黑丝”。只提取衣服、手套、丝袜、鞋和身体服饰，保留原版脸、头发、体型与目标原头饰；源兔耳、发带、发饰、头发和裸身不进入成品。

本例使用 Blender 5.1.2、UE 4.26.2。技能中的参考路径与数值是实测定位资料，不要求其他模型照抄。

## 本例实际制作链

1. 保留原 ZIP、旧衣装文件和官方基线，在新工程中解压。处理 ZIP 中文文件名编码；读取两套 PMX 的顶点、面、材质、骨骼与真实贴图引用。
2. 核对 FashionDataTable 的行路行与 ArtPackID；活动时装表覆盖仍指向 fashion_dress_6。实际女性 Mesh 为 `/Game/Resources/Characters/Player/female_01/f_player_09/f_player_09.f_player_09`，Skeleton 为 `/Game/Resources/Characters/Player/female_01/f_player_Skeleton.f_player_Skeleton`。运行时起初显示 f_player_86，安装前的组件快照已确认切到 f_player_09；独立脸发组件另行记录。
3. 外部 PMX 的 25,708 个顶点、39,082 个三角面、252 根源骨骼用于拆分和适配，不直接替换整个人物。实测提取材质分区 3、4、5、21、23～27，排除裸身/颈部 0、1、2、6 和头部相关 7～20、22；这些编号只对本 ZIP 有效，选择依据是实际部位、UV/纹理和源骨绑定。目标 f_player_09 的检查未发现衣装中混入待保留的头饰面，头部资源不进入覆盖包。
4. 原版身体与原版 142 根骨骼作为约束，改服装。旧身体在旧靴子和旧衣服遮挡处缺少小腿/髋部，分别补对应官方缺失皮肤。已有原版身体顶点保持位置不变，源裸身仅作未导出的拟合参考。
5. 以关节锚点与分区变形初次适配；胸衣、丝袜、手套取对应部位的身体权重，限制影响数并归一化。胸口按体表修正衣料间距，手套上缘补服饰内衬，下垂裙片兼顾裙摆链与同侧腿部运动。
6. 使用保存后的生产模型检查原生走路、跑步、抬臂动作及构造抬臂/屈肘姿势。用户指出髋侧两块灰色扁片后，只修相关体表参考、丝袜/裤部贴合和局部权重；保留已接受胸衣、肩袖、鞋、脸发与其他区域。
7. 显式生产导出，独立 UE 工程重新导入与完整 Cook；回读 Mesh 的骨架、参考姿态、几何和权重。暂存仅包含替换 Mesh 与私有材质/纹理，生成 Pak、转换当前客户端容器格式、完整解包逐文件比对，再同名配对已经验证的 Sig 模板。

## 髋部两块扁片的诊断与修复

扁片属于丝袜近端腿/髋部几何，不是手上饰件或额外头部部件。旧作者身体的躯干、股根与下体参考不连续，最近点吸附把上段丝袜压到错误边界；该区还混入了裙摆影响。按高度切片、实际面覆盖和权重检查后，能定位到局部体表与来源对应的问题，无需重新分析整个角色或拆整套素材。

先为实际缺失的髋部补对齐的官方皮肤，本次补片记录 1,584 个源面。保留既有原版顶点位置。再从保存的源几何恢复上段丝袜/裤部，重新贴合连续局部体表，平滑过渡到已接受腿段，并去掉贴身区的裙摆/披风影响。

第一次局部重建仅用 UV 最近三角对应，重叠 UV 误选其他部位，造成跳点和尖刺。正确修复使用保存的源顶点身份；本例在明确的一次细分流程中验证原顶点对应与 UV、拓扑关系，新边点由两个已确认源端点重建。这个前提成立才可沿用索引，不能把“前 N 个顶点不变”当作任意 Blender 操作的通用保证。

同一跑步姿势前后对比确认两侧扁片消失；静止近景保持原服装 UV 和实际丝袜纹理，原版身体的既有比例不因修复改变。

## 手套与裙片的动作修复

手套上缘在静止尚可，跑步时仍露肤。局部增间距与权重对应之后，为真正被手套覆盖的原版皮肤拓扑生成薄服饰内衬，使用手套 UV 与相同局部蒙皮。只按面中心距离选区的第一版内衬越过袖口，出现黑色锯齿；改为检查所有面角的实际手套覆盖，最终保留 246 个内衬面，并复查同一动作。

裙片完全随腿会拉碎图案，改为纯辅助链又被迈出的腿穿过。最终按前后/左右与高度平滑结合原版裙摆链和同侧大腿运动，同帧检查走路侧面及跑步正面；保留裙片静止位置、材质和 UV。系数由本次几何与动作调试确定，不写成下一套长裙的固定参数。

## 导入与回读中的实测边界

独立 UE 工程复制旧资源后，replace_existing 导入曾保留 Anastasya 的旧材质槽。只在作者副本中清理旧 Mesh 再导入，核对实际新槽与材质引用。FBX 日志包含 bind 重建，回读最终 142 根骨骼的序列、父级与局部参考数据，与上一套用户接受的 cooked Mesh 完全一致，才接受该导入结果。

Cook 位置回读最大差异约 `4.29e-6 cm`。权重不能要求原浮点值与 Cook 完全相等：此导入实测裁掉 `<0.01` 的影响，重新归一化，再用 8-bit 表示，次要影响取整后残差回到最大影响。原始权重最大差约 0.02012；确认裁剪后最大差约 0.01122，落在该编码的 `(影响数-1)/255` 界内，同时影响骨集合一致。这个规则只适用于已经确认的本次导入/编码；其他格式需先查规则，不能因回读失败随意放宽容差。

冲突扫描读取主索引与完整目录索引：本例 61 个活动 Mod 包均解析成功，无直接 f_player_09 覆盖；找到的时装表包需要继续核对目标行，而不是只搜包名。纯搜主索引曾得到空结果，不能作为“没有覆盖”的证据。

工具异常还包括 Blender 空场景没有 World、普通 Python 被同目录 inspect.py 遮蔽标准库，以及 UE 缓存默认写不可写用户目录。分别修正数据初始化、脚本名称与任务内 DDC 图；不因这些异常重做素材或假定宿主退出码代表业务成功。
