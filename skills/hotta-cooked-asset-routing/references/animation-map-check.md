# 动画爆体：客户端映射检查

适用于自定义 AnimSequence 导入、重定向、Cook 或轨道映射修改。源预览正常却多个动作全身扭曲时，优先检查这里。

1. 独立取得实际挂载的客户端 Skeleton：按序骨名、父级、reference TRS 和来源。作者工程同名 Skeleton 不是权威。
2. 对比作者骨表；导入可能新增辅助骨，骨数相同也可能顺序不同。同 GUID 不证明映射一致。
3. 转索引前独立保存预期轨道骨名。验证时不能从待测 map 生成期望。
4. 读取最终 staged cooked 动画的 TrackToSkeletonMapTable 和 CompressedTrackToSkeletonMapTable。
5. 对每条实际轨道核对客户端索引指向预期名称，拒绝越界、缺失、歧义和非预期重复；范围内错误同样失败。
6. 编码器裁剪/重排时按已知解码身份对应，不假定任意 codec 的布局，不跳过压缩 map。
7. 用客户端参考解码最终关键帧，在真实目标 cooked Mesh 上回放。
8. 网格权重对应网格自己的骨表，通过名称/父级与客户端骨表连接，使用真实 mesh bind。不能直接套另一骨表的矩阵数组。
9. 检查新增 clip 的初始、极值、恢复/循环及连续动作；验证中不做自动重命名或 rest 拟合来掩盖错误。
10. 封包回读后确认仍是同一成品，再测试客户端实际使用者及受影响的中止/恢复。

若 rest 或层级不兼容，需要真正重定向，索引修补不足。不能为一个动画替换共享客户端 Skeleton。

缺少可信解码器时标为未验证。离线回放不覆盖 AnimBP、IK、物理、LOD 或胶囊放置。源动画外观、骨架绑定、封包完整和游戏播放分别给出结论。

## 外部 VMD 的另一条检查路线

进程内 VMD 不经过 AnimSequence 压缩轨道表，检查其源语义、坐标/单位、实际目标父级和参考 TRS、写入后的骨骼值及实机动作。不能因没有 cooked 压缩表就推断文件损坏，也不能以 VMD 解析通过宣称 cooked 绑定通过。

分别识别骨骼、Morph 和相机轨道。动作骨骼记录 111 字节、Morph 记录 23 字节仅用于已确认的 VMD 2 格式；轨道名称按 CP932，文件路径按 Windows Unicode 处理。标准别名映射有边界，不认识的模型专属 Morph 不能凭数量计入已适配。

独立表情与动作使用同一时间，表情权重线性插值并限制范围；动作源既可能以足 IK 驱动，也可能直接提供大腿、膝盖和脚踝 FK。不要只验证第一份动作后声称任意 VMD 均支持。
