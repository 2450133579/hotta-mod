# 幻塔 Cooked 资源路线诊断

目标决定工具。能够解析、能够保存、Cook 成功、封包一致与游戏正确运行分别证明不同环节。

## 路线选择

| 目标 | 优先方法 |
|---|---|
| 查看引用、父材质和参数 | 完整提取后用适配的只读解析器或 UModel |
| 复用原生时变效果 | 引用游戏已有原生资源，按需要隔离使用者 |
| 原路径纹理替换 | UE4.26 Cook，或已验证的严格同格式载荷替换 |
| 修改拓扑、权重、材质分区、UV、顶点色 | 回到作者模型并完整重新 Cook |
| 自制材质实例 | 使用已证明可用的原生父材质与私有子实例路线 |
| 材质能加载但外观错误 | 先查实际面归属与生效输入链 |
| 自定义动画扭曲或全身拉伸 | 查最终 raw/compressed 轨道对客户端骨架的映射 |

- 工具选择见 [工具与格式边界](references/tool-boundaries.md)。
- 材质、载荷和外观问题见 [资源与外观诊断](references/resource-diagnosis.md)。
- 动画问题见 [客户端动画映射](references/animation-map-check.md)。

运行时 VMD 的异常先分辨发生在资源本身还是解析器、Lua 参数、网格代理、附属件和音频设备；对应案例补在以上三个主题中。未修改 cooked 字节的故障，不默认进入重新 Cook 或 Pak 修补。

## 检查深度

已由 UE4.26 生成且路线未变的资源，检查 Cook、必要 sidecar、预期引用、暂存清单、Pak 回读与对应客户端结果即可。

提取后修改、二进制补丁、重定位或未知格式，增加完整文件组、文件头分类、结构化读写及格式检查。不要默认深审每个没有变化的资源。

## 解析失败时

对支持情况未知的 UAssetGUI/UAssetAPI，先确认配套文件完整，再尝试原始完整提取和 UModel 保存的分析副本。两类都无法解析所需导出/属性时，停止此解析路线，转只读检查、原生引用或重新 Cook。

不要反复换近似版本、猜偏移或以等长字符串替换冒充正确重定位。UModel 保存副本有分析价值，但不自动证明资源身份与导入表能够迁移。

## 新材质路线验证

原生对照或无贴图覆盖的子实例 → 一个明显参数/纹理 → 一个材质槽 → 必要的多个槽。每一步看对应客户端结果。无覆盖对照已出现灰格时停止，不继续叠加贴图变量。

路线被证明后，后续保持同一结构的修改可以直接验证本次假设，不反复执行整套阶梯。

## 输出

记录资源身份、必要配套文件、工具实际支持范围、修改项、可达引用、封包回读和实机结论。已知纹理的尺寸/Alpha、某模型骨数或某资产偏移只能作为对应对象的条件，不推广为全局规则。
